1. ChemE-as-Code: An Open-Source Platform for Agentic AI in Chemical Engineering

摘要

这篇论文提出 ChemE-as-Code，一个面向化学工程的开源平台，让基于大语言模型的 AI 智能体在工程环境中执行计算任务，同时让工程师能够核查其工作。平台覆盖从催化、流程模拟到工厂布局、HAZOP 和生命周期评估等工具，并通过“技能”指导通用智能体调用这些工具。工程文件以机器可读、可版本化的方式在 Git 中链接管理，计算在 LLM 之外运行，每个数值都记录来源，自动检查按文件和行号报告不一致与过期结果。在一个氨案例中，智能体将书面任务发展为初步基础工程包，设计会话的 API 成本为 224 美元；植入故障和工程变更测试表明，检查只能发现规则覆盖范围内的问题，因此其定位是辅助而非替代人工审查，且该设计未经独立工程师评审。

为什么重要

对工程技术与研发管理者而言，这展示了“LLM 智能体 + 可追溯计算 + 自动校验”的落地范式，可作为评估 AI 辅助工程流程可靠性与审查成本的参考；对学习成长者，它提供了智能体系统设计中“计算与生成分离、来源可审计”的典型案例。

值得记住

2. tok: a textual concrete syntax of BPMN and DMN for humans and AI agents

摘要

这篇论文提出 tok——一种面向 BPMN 2.0.2 流程模型和 DMN 1.5 决策模型的纯文本记法，作为这两种标准元模型的替代具体语法。单一引擎可校验 tok 文档是否符合两项标准、将其编译为带自动图表的 XML，并通过 Model Context Protocol 服务语言模型应用。论文报告了一项研究：tok 模型比 893 个文件中最小的 BPMN XML 少用 2.2 倍 token，比原始导出文件少 7.7 倍；检查器能捕获 98.2% 的注入故障，而 XML Schema 加 bpmnlint 为 85.8%。四个初次接触 tok 的语言模型仅凭一页参考就能为 85.7%–100% 的流程描述写出有效 tok，且最强模型写 tok 比写 BPMN XML 少用 25% 和 19% 的 token。

为什么重要

如果你从事流程建模、低代码/自动化或 AI 智能体工作流设计，tok 提示了一条用更少 token、更高校验率让 LLM 直接生成和操作业务流程模型的路径，对降低智能体调用成本和提升可靠性有直接参考价值。

值得记住

tok 检查器对 1,411 个注入故障的检出率为 98.2%，显著高于 XML Schema 加 bpmnlint 的 85.8%——文本记法在可校验性上反而可能优于 XML 生态。
